## Project Overview

**ObiOne** — Observatório de Projetos. PhD-level course project (TAES — Tópicos Avançados em Engenharia de Software, UPE/POLI), supervised by Prof. Ivaldir Honório de Farias Júnior.

ObiOne is an **observatório-de-portfólio para consultorias de projetos**: it observes consultancy projects through the lens of the *Modelo de Observatório de Projetos* (MPO — Vieira, 2022, Quadro 37, 44 attributes), curates a **semi-open community** (the consultancy curates; each client sees only their own project), and surfaces cross-project knowledge by domain (phenomena, lessons, governance, discussions).

Repository: `raniel90/obione` (this repo). The application is a **v2 rewrite**:

- **`backend/`** — REST API in **Java 21 + Spring Boot 3.5** (Maven).
- **`frontend/`** — SPA in **React 19 + TanStack Start/Router** (bun).
- **`backend/v1/` and `frontend/v1/`** — the previous stack (FastAPI/Python + React/Vite), **archived** for reference. Do not modify v1.

## Prerequisites & Setup

```bash
# 1. JDK 21 (project requires 21; default macOS JDK may be older)
brew install openjdk@21
export JAVA_HOME="$(brew --prefix openjdk@21)/libexec/openjdk.jdk/Contents/Home"
# (add the export to your shell profile, or prefix mvnw calls with it)

# 2. Backend: build + tests (downloads Maven + deps on first run)
cd backend
./mvnw -q -DskipTests package      # build the fat jar
./mvnw test                        # run tests (H2)

# 3. Frontend
cd frontend
bun install
```

## Common Commands

**Backend** (run from `backend/`, with `JAVA_HOME` pointing at JDK 21):

```bash
./mvnw spring-boot:run     # DEV mode — devtools hot-reload, LiveReload on :35729; serves http://localhost:8080/api
./mvnw test                # unit/integration tests
./mvnw -DskipTests package # build target/obione-backend-*.jar
```

**Frontend** (run from `frontend/`):

```bash
bun run dev      # Vite dev server → http://localhost:5173
bun run build    # production build
bun run lint     # ESLint
bun run format   # Prettier --write
```

> Run the backend in **dev mode** (`./mvnw spring-boot:run`) for day-to-day work — it hot-reloads via spring-boot-devtools. Running `java -jar target/...` directly requires `java` itself to be JDK 21 (the build is class-file v65); `spring-boot:run` already uses the wrapper's JDK 21, so prefer it.

## API & Wiring

- Backend listens on **`http://localhost:8080`** with **context-path `/api`** → every endpoint is under `/api/...` (e.g. `GET /api/health`, Swagger `/api/swagger-ui.html`, H2 console `/api/h2-console`).
- CORS allows the frontend origins `http://localhost:5173`, `:3000`, `:8081` (see `config/SecurityConfig.java`).
- Frontend talks to the backend via `frontend/src/services/apiClient.ts` → `API_BASE_URL = "http://localhost:8080/api"` (hardcoded; no `.env` needed). Auth token is stored in `localStorage["obione-auth"]`.
- **Auth is a mock token**: `AuthService` validates email + BCrypt password against the `users` table and returns a fixed token whose session is held **in memory** (`ConcurrentHashMap`). Restarting the backend invalidates all sessions. `SecurityConfig` currently uses `anyRequest().permitAll()` (MVP) — real authorization is not enforced at the filter yet.
- **Demo data is seeded on startup**: each context ships a `*DataSeeder` (e.g. `users/seed/UserDataSeeder`, `projects/seed/ProjectDataSeeder`) that populates the in-memory H2 on boot. There is no separate seed/migration step — just start the backend.
- `backend/docker-compose.yml` is **broken** (its contents are a copy of `application.yml`, not a Compose file). Ignore it; dev needs no DB container because H2 is in-memory.

## Architecture

**Backend** — package-per-bounded-context under `br.com.obione.<context>`, each split into the standard layers:

- `controller/` — thin `@RestController`s; map DTO ⇄ service.
- `service/` — `@Service` business logic (`@Transactional`).
- `repository/` — Spring Data JPA `@Repository` interfaces.
- `entity/` — JPA `@Entity` domain models; `enums/` for value types.
- `dto/` — request/response DTOs (Java `record`s).
- `mapper/` — entity ⇄ DTO mapping.
- `seed/` — startup data seeders.
- Cross-cutting: `common/exception/` typed exceptions + `GlobalExceptionHandler`; `config/SecurityConfig`.

**Frontend** — TanStack file-based routing: a file in `src/routes/` is a route (`login.tsx` → `/login`, `projects.$id.tsx` → `/projects/:id`, `__root.tsx` = layout). `routeTree.gen.ts` is generated — never edit by hand. Server calls go through `src/services/` (`apiClient.ts` + per-context service modules), with mapping in `apiMappers.ts`. Server state via react-query; forms via react-hook-form + zod.

## Code Conventions

**Java/Spring**

- One bounded context per package; respect the `controller/service/repository/entity/dto/mapper` layering. No business logic in controllers.
- DTOs as `record`s; entities annotated with JPA; use Lombok for boilerplate.
- Throw typed exceptions from `common/exception` (e.g. `ResourceNotFoundException`, `UnauthorizedException`); let `GlobalExceptionHandler` translate them to HTTP responses.
- Endpoints are relative to `/api` (context-path) — don't re-add `/api` in `@RequestMapping`.

**TypeScript/React**

- Routes live in `src/routes/`; let the router plugin regenerate `routeTree.gen.ts`.
- All network access goes through `src/services/` (don't `fetch` ad-hoc in components); keep `API_BASE_URL` single-sourced in `apiClient.ts`.
- Forms: react-hook-form + zod. Run `bun run lint` and `bun run format` before committing.

## What NOT to do

- Don't modify `backend/v1/` or `frontend/v1/` — they are the archived previous stack.
- Don't hand-edit `frontend/src/routeTree.gen.ts` (generated).
- Don't run `java -jar` with a JDK < 21; prefer `./mvnw spring-boot:run`.
- Don't rely on `backend/docker-compose.yml` (broken) or expect an external DB in dev (H2 is in-memory).
- Don't add documentation files (`*.md`) outside `atividades/` unless explicitly asked.
- Don't name the consultancy that provided the `.docx` projects — refer to it only as "consultoria" or "organização executora".
- Confirm the current date with the user before crystallizing absolute dates in academic docs (history of slipping dates).
- Merge to `main` only via PR (`gh pr create`); confirm with the user before merging.
